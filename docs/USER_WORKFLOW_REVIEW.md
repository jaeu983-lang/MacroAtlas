## 1. 사용자는 두 가지 방식으로 시작할 수 있다

- **기관을 모르는 요청:** “국가별 미국 국채 보유잔액의 월별 데이터를 찾고 싶어.”
- **기관을 지정한 요청:** “미국 재무부 TIC의 국가별 미국 국채 보유잔액을 찾고 싶어.”

둘 다 요청한 통계의 의미에 맞는 기관·데이터셋·시계열 후보를 제안하는 대상으로 본다.
기관을 지정했더라도 그 기관에 원하는 통계가 있는지 확인한다. 다른 기관이 더 적합하면
이유와 대안을 설명하되 지정 기관을 사용자에게 알리지 않고 바꾸지 않는다.

## 2. 사용자 작업 1 — 데이터 탐색과 후보 제안

요청의 개념·대상·제약을 해석하고 공식 출처와 저장된 지식에서 후보를 찾는다.
근거가 충분하면 후보 1개를, 여러 해석이나 출처가 가능하면 여러 후보를 제시한다.
찾지 못하면 어떤 부분이 미확인인지 보고하며 후보 수를 맞추려고 만들어내지 않는다.

이때 “추측”은 **확인할 후보를 세우는 것**이다. 기관 적합성의 가설과 공식 근거로
확인한 데이터 존재 여부를 구분하고, 확인하지 않은 API URL·시계열 코드를 지어내지 않는다.

후보별로 다음을 보여주는 것이 좋다.

| 항목 | 사용자가 판단할 내용 |
|---|---|
| 기관·통계명·공식 링크 | 어느 출처의 어떤 자료인가 |
| 데이터셋/시계열 식별자 | 실제로 확인했는가, 아직 후보인가 |
| 정의·차이 | 잔액/거래액, 자산/부채, 명목/실질 등 요청과 맞는가 |
| 지역·단위·주기·가능 기간 | 원하는 범위를 제공하는가 |
| 추천 이유·불확실성 | 왜 이 후보인가, 무엇을 더 확인해야 하는가 |
| 접근 상태 | 키 필요 여부, 지원 커넥터 여부, 수집 가능성 미확인 여부 |

**메타데이터 탐색은 이 과정에서 시스템이 내부적으로 수행한다.** 사용자가 별도로
“메타데이터 discovery를 실행해”라고 말할 필요는 없다. 필요한 정의·차원·코드·기간을
확인하고 핵심만 설명한다. 메타데이터로도 통계 의미가 모호하면 사용자에게 확인한다.
공식 문서 확인, 메타데이터 응답 확인, 실제 관측치 수집 성공은 서로 다른 검증 상태다.

작업 1의 결과는 후보와 근거이며 대량 관측치 다운로드는 아직 하지 않는다.
후보 발견과 실제 수집 지원은 다르므로 “자료는 발견했지만 현재 커넥터는 미지원”도 가능하다.

## 3. 두 작업 사이 — 원하는 데이터와 출력 조건 확인

후보를 실제로 내려받기 전에 부족한 조건을 한 번에 묻는다.

> “이 후보는 국가별 국채 **보유잔액**입니다. 이 데이터가 맞나요?
> 수집할 국가·기간·주기와 결과 파일 형식을 알려주세요.”

확인할 핵심은 선택한 후보, 통계 의미, 국가/차원, 시작·종료 기간, 주기,
단위/변환 필요 여부, 결과 형식(CSV/XLSX 등)과 저장 위치다.
선택지는 실제 지원 가능한 형식으로 제시하고, 변환이 필요하면 원본과 구분해 설명한다.
기간의 데이터 가용성과 최신/특정 개정판 요구도 확인한다. “모름”을 임의 값으로 채우지 않는다.

**사용자가 이미 명시한 조건은 다시 묻지 않는다.** 후보와 조건이 모두 명확하고
수집을 명시적으로 요청했다면 요약한 조건으로 진행할 수 있다. 반대로 필수 정보가
없거나 중요한 개념이 모호하면 임의로 전체 기간·전체 국가를 다운로드하지 않는다.
이 사용자 확인은 네트워크·접근권한 승인을 대신하지 않는다.

제안한 후보와 사용자가 선택한 후보, 확정된 조건을 연결해 보존하는 계약이 필요하다.
이는 현재 Python의 `resume(approved=True)`와 다른 제품 기능이다. 해당 플래그는 실행
상태의 검토 확인일 뿐 후보 선택이나 출력 조건 입력을 구현한 것은 아니다.

## 4. 사용자 작업 2 — 확정된 데이터를 실제 수집하고 결과 제공

확정한 후보·조건에서 접근 경로를 검증하고 수집·파싱·검증·저장을 수행한다.
수집 직전 메타데이터가 오래됐거나 출처가 변경됐으면 필요한 부분을 재확인한다.
정의나 코드가 달라졌다면 사용자 선택을 조용히 다른 데이터로 대체하지 않는다.

결과는 파일 하나의 위치만 알려주는 것보다 다음을 함께 제공하는 것이 좋다.

- 요청한 데이터와 실제 수집 범위, 성공/일부 성공/실패 여부.
- 원본 파일과 요청한 출력 파일의 위치, 내용 미리보기.
- 기관·식별자·원URL·수집 시각과 통계 정의·단위·주기.
- 검증 결과, 결측·실패·미지원 범위 및 안전한 다음 조치.

기관별 API 키는 필요한 기관만 설정한다. 키 불필요 경로는 익명 접근하고,
필수 키가 없는 경로만 설정 필요로 중단한다. 실제 키는 문서·프롬프트에 입력하지 않는다.

후보를 이미 알고 있는 사용자는 작업 1 전체를 반복하지 않고 작업 2로 시작할 수도 있다.
이 경우에도 식별자·통계 의미·가용성 확인은 생략하지 않는다.

## 5. 대규모 요청은 별도 실행 계획이 필요하다

기획에는 BIS bulk/ZIP, 대용량 예산, 중단·재개가 있다. 그러나 “여러 기관·국가·지표를
얼마나 크게 한 작업으로 처리할지”의 구체적인 기준과 사용자 절차는 아직 부족하다.

추가할 수 있는 흐름은 다음과 같다. **현재 구현됐다는 뜻은 아니다.**

1. 대상·기간·지표 수와 예상 요청 수/용량을 제시한다. 추정 불가한 값은 미상으로 표시한다.
2. 일부 국가·기간의 소규모 샘플로 정의와 출력 형태를 먼저 확인한다.
3. 국가·지표·기간별로 나눌 단위, 시간·호출·용량 상한과 저장 형식을 확정한다.
4. 작은 단위로 수집·기록하며 기관의 공식 bulk 경로와 호출 제한을 따른다.
5. 성공·실패·미실행 단위를 따로 보고하고 유효한 성공분을 보존해 재개한다.

대용량을 무조건 한 XLSX 파일에 넣기보다 실제 지원 형식과 파일 분할 계획을 먼저 제안한다.
서로 다른 통계의 단위나 정의가 다르면 이름만 보고 한 표로 합치지 않는다.
현재 03회차의 1개 국가/지표·1~10년·1페이지·1 MiB 제한은 이 검토 때문에 해제하지 않는다.

## 7. 01~03회차에 반영 가능한지 — 코드 수정 전 검토

| 기존 작업물 | 가능한 보완 방향 | 현재 상태/이번 결정 |
|---|---|---|
| 01: 공통 계약 | 요청 조건, 후보 제안/선택, 출력 설정의 명시적 모델 | 추가 후보. 기존 모델은 아직 이 제품 계약을 구현하지 않음 |
| 02: Orchestrator/이력 | 탐색 결과와 선택·조건을 수집 작업에 연결하고 확인 대기 이력 보존 | 기반은 재사용 가능. 현재 고정 계획을 임의 수정하지 않는 설계가 필요 |

| 05~08: 탐색·메타데이터·후보 연결 | 기관 추천과 후보 비교, 내부 메타데이터 확인, 사용자 선택 흐름 | 핵심 기능의 주된 구현 위치 |
| 09~10: 확대·안정화 | 형식 확대·분할 실행·예산·부분 실패 복구 | 대규모 작업의 구현 후보 위치. 상세 범위와 게이트 보완 필요 |

01~03회차에 전체 기관 추천·자연어 탐색을 한꺼번에 넣는 것은 기존 범위와 맞지 않는다.
요청/선택/출력의 **계약과 연결 기반**을 먼저 보완하는 것은 검토 가능하다.
저장된 계획은 변경 불가이므로 탐색 이후 조건 확정 시 새 수집 작업을 만들고 상위 요청·
후보 근거로 연결하는 방안을 제안한다. 구체 ID·저장 스키마는 아직 결정하지 않았다.

사용자가 구현을 별도로 요청하기 전까지 01~03회차 코드는 변경하지 않는다. 이번 검토는
04회차 이후 개발을 시작하거나 완료 처리하는 작업도 아니다.

## 8. 사용자가 줄 수 있는 프롬프트 예시

아래는 **목표 사용 흐름을 설명하는 예시**이며 현재 프로그램의 자연어 명령 문법이 아니다.
현재 코드는 일반 기관 추천·출력 파일 생성 기능을 아직 제공하지 않는다.
수집 예시는 지원 커넥터·허용 네트워크·필요 인증이 준비된 경우를 전제로 한다.

### 기관을 모를 때 — 후보 탐색

> 국가별 미국 국채 보유잔액의 월별 데이터가 필요해. 적합한 공식 기관과 데이터
> 후보를 제안해줘. 거래액과 잔액을 구분하고, 추천 이유·가능 기간·단위·출처를
> 알려줘. 메타데이터도 확인하되 지금은 실제 데이터 다운로드는 하지 마.

### 기관을 지정할 때 — 후보 확인

> 미국 재무부 TIC에서 국가별 미국 국채 보유잔액 데이터를 찾아줘.
> 원하는 개념에 맞는 후보와 차이를 보여줘. 그 기관에서 찾지 못하면 이유와 다른
> 공식 출처 후보를 알려줘. 기간과 출력 조건은 후보를 본 다음 정할게.

### 후보를 선택한 뒤 — 실제 수집

> 앞에서 제안한 후보 1번의 보유잔액 데이터가 맞아. 일본·중국에 대해 2015년 1월부터
> 최신 가용 월까지 월별 원단위로 수집해줘. CSV를 원하고, 실제 저장 위치를 알려줘.
