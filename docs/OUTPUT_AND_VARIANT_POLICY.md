## 1. 출력은 “전달 방식”과 “파일 형식”을 나눠 묻는다

- 파일: 구현된 경우 XLSX/CSV 등의 형식과 저장 위치를 선택한다.
- 링크: 실제 데이터로 가는 공식 다운로드/API/뷰어 링크를 유형·제약과 함께 제공한다.
- 둘 다: 데이터 파일과 검증된 데이터 링크를 함께 제공한다.

현재 지시에 방식이 없으면 **출력을 만들기 전에 묻는다**. 이전 선호는 질문의 추천 순서를
도울 수 있지만 사용자의 이번 선택을 대신하지 않는다. 이미 “엑셀로”, “링크만”, “둘 다”라고
했으면 같은 질문을 반복하지 않고 누락된 필수 조건이나 미지원 부분만 묻는다.

| 실제 확인 결과 | 예시 안내 |
|---|---|
| 링크와 XLSX 모두 지원 | “엑셀 파일, 데이터 링크, 둘 다 중 어떤 방식으로 드릴까요?” |
| 확인한 경로에 링크 없음, 파일 지원 | “확인한 범위에서 제공 가능한 데이터 링크가 없어 링크 전달은 선택할 수 없습니다. 지원 파일 형식 중 무엇으로 드릴까요?” |
| 링크 미확인 | “데이터 링크는 아직 확인되지 않았습니다.” 확인을 계속하거나 현재 지원되는 다른 방식의 선택을 묻되 ‘없음’으로 단정하지 않음 |
| 링크만 지원 | “현재 가능한 전달 방식은 링크입니다. 이 방식으로 드릴까요?” |
| 사용자가 고른 방식이 미지원 | 이유와 가능한 대안을 설명하고 다시 선택받음. 다른 방식으로 자동 변경하지 않음 |

링크만 전달할 때는 검색/검증에 필요한 최소 접근만 수행한다. 전체 관측치를 내려받거나
파일을 만들 필요는 없다. 제공한 링크와 대상·조건·확인 시각을 기록하며 **링크 전달 완료**를
**수집·파싱·품질 검증 완료**로 표시하지 않는다.

## 2. 링크 탐색은 독립 경로로 병행한다

목표 구조는 “통계 후보·메타데이터 탐색”과 “공식 데이터 링크 발견·검증”을 병행하고,
같은 후보 ID·정의/개정·선택 조건을 기준으로 결과를 합치는 것이다. 메타데이터 확인을
생략하는 병행이 아니다. 아직 후보가 불명확하면 찾아둔 링크는 미확인 결과로 남긴다.

개념 모듈: discovery의 링크 발견/검증 인터페이스 + 기관별 링크 어댑터.
기존 기관별 Python 분리는 유지한다. 실제 병렬 실행기·스레드·워크플로 추가는 별도 구현이며
이번에 에이전트나 네트워크 작업을 병렬 실행하지 않았다. 권한/호출 예산도 별도로 따른다.

링크에는 URL, 유형, 후보/조건 연결, 확인일, 가용 상태, 수동 필터 필요 여부,
권한·만료/공유 제약 및 근거를 기록한다. 다음은 구별해야 한다.

- 실제 다운로드/API 요청: 선택 데이터와 조건이 반영됐는지 확인한다.
- 공식 데이터 뷰어: 해당 데이터로 연결되는지와 기간/차원을 사용자가 다시 선택해야 하는지 알린다.
- 일반 기관 홈페이지/설명서/카탈로그: 출처 안내일 뿐 실제 데이터 링크 선택지를 대체하지 않는다.
- 키·토큰 포함 URL/만료 링크/공유 권한 없는 경로: 유효한 전달 선택지로 내놓지 않는다.

available만 선택지에 넣는다. unavailable은 조사한 경로·범위와 함께, unknown은 미확인으로,
blocked는 제약 사유와 함께 표시한다. 한 번 못 찾은 것을 기관 전체에 링크가 전혀 없다는
주장으로 확대하지 않는다. 링크가 있다고 통계 의미나 요청 기간이 맞다고 단정하지 않는다.

## 3. 비슷한 통계는 “개념 그룹 + 변형 차이”로 보여준다

예를 들어 같은 산업생산 지표에 계절조정/비조정 시계열이 있으면 독립된 추천 두 개를
동등하게 나열하기보다 한 그룹 안에서 차이를 표시한다. 두 원자료·식별자는 각각 보존한다.
묶음은 보기 방식이며 같은 값·상호 대체 가능성·자동 병합을 의미하지 않는다.

묶음 근거는 정의·대상·통계 범위·방법론이다. 표시할 차이는 계절조정, 명목/실질·기준년,
수준/증감률, 주기, 단위/배율, 잠정/수정 상태, 가용 기간과 출처다. 잔액과 거래액처럼
경제적 개념이 다른 것은 별도 그룹으로 구분하고 관계만 설명한다.

## 4. 언제 묶어 보여주고, 언제 먼저 물을까

| 상황 | 기본 동작 |
|---|---|
| 중요한 특성이 이번 요청에 명시됨 | 맞는 변형으로 좁히고 왜 다른 변형을 제외했는지 설명 |
| 같은 개념의 소수 변형, 비교 목적 | 한 그룹과 차이표를 먼저 보여주고 필요한 선택만 받음 |
| 변형이 많거나 의미가 크게 갈림 | 가장 중요한 모호함부터 짧게 질문하고 다음 후보를 좁힘 |
| 사용자가 “모두 비교”라고 요청 | 변형을 구별해 제안. 수집/파일 합치기·변환은 별도 조건 확인 |
| metadata가 미상/충돌 | 미상을 표시하고 근거 재확인. 임의 계절조정·단위·동등성 추정 금지 |

질문 예시: “단기 움직임을 보려는 자료인가요, 공표 원계열을 비교하려는 자료인가요?
계절조정/비조정 두 변형이 있습니다.” 목적만으로 조정 여부를 자동 확정하지는 않는다.
질문은 선택을 줄이는 데 필요한 만큼만 하며, 모든 특성을 매번 체크리스트처럼 반복하지 않는다.

## 5. 사용자 피드백으로 작업마다 표현을 조정한다

“이번에는 조정 여부별로 묶어줘”, “다음에는 차이를 먼저 물어봐”, “이 기관에서는 원계열
우선” 같은 명시 지시를 작업/기관/개념 범위와 함께 기록한다. 적용 범위가 모호하면 그
작업에만 적용하고, 영구·전기관 선호로 확대하지 않는다. 선호 변경/취소도 추적한다.

우선순위는 현재 명시 지시 → 해당 범위에서 검증된 유효 선호 → 위 기본 표현 정책이다.
이는 그룹/질문 표현을 조정하는 정책이며 통계 정의·선택·출력 방식의 필수 확인을 우회하지 않는다.
새 요청에서 출력 지시가 없으면 선호가 있어도 전달 방식을 묻는다. 명시적으로 “앞과 같은
방식”이라고 지시한 경우에는 이전 설정의 적용 가능성을 확인해 재사용할 수 있다.

## 6. 구현 위치·검수·현재 경계

- 05~08회차: 링크 발견·검증, 변형 메타데이터, 그룹/질문·출력 선택 연결.
- 09~10회차: 지원 파일 출력과 링크 전용 실행 분리, 만료·권한·조건 불일치 대응.
- 11~12회차: 표현 선호의 범위·검증·변경/취소·현재 지시 우선 적용.

추가 테스트는 링크 상태 4종, 홈페이지/데이터 링크 구별, 미지시 출력 질문·명시 지시
중복 질문 방지, 링크 전용의 다운로드/파일 생성 0회, 조건·개정 불일치 링크 제외,
SA/NSA 구별·미상 보존·다른 개념 분리, 묶음의 비합산, 선호 범위·상충·취소를 포함한다.

값 계약 확장에 DeliverySpec(file/link/both/미정), 파일 형식과 DataLink 결과,
후보 그룹/변형 속성·선택 조건을 반영했다. 표현 선호 연결은 후속 범위다. 기존 OutputSpec.format에
문자열 `link`를 넣는 것만으로 이 기능이 구현된 것으로 보지 않는다.
현재 ConfirmedSelection의 단일 후보 계약도 복수 변형 선택을 자동 지원하지 않는다.
확장은 GroupedProposal/DeliveryOffer/ConfirmedDelivery로 분리해 기존 JSON/fingerprint를
유지한다. 확정은 한 후보에 한정하며 복수 변형을 자동 선택하지 않는다.
검증 선언은 실제 웹 검증을 대신하지 않는다. DataLink.available은 공개/공유 가능/근거/확인 시각을
명시해야 하고 선택 시 만료를 검사한다. 링크 전용은 OutputSpec·로컬 exporter를 요구하지 않는다.

최초 정책 반영은 문서 변경이었고, 이후 사용자의 요청으로 확장 값 계약/테스트만 구현했다.
실제 API·링크 존재 여부를 새로 확인하지 않았다. 보완 02·03과 04회차는 미착수다.
최신 변경 파일·테스트 결과·제한은 docs/ALIGNMENT_01_EXTENSION_REPORT.md 참조.
