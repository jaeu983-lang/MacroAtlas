# 23회차 기획 — 목표 사용자 업무 관찰

> **현행 사용 안내:** 이 문서는 초기 CSV status→export 시나리오의 준비 기록이다. 실제 세션은 40회차에서 28–39회차 gate 통과 후 진행한다. 과거 CSV 과제를 현재 workbook 사용성 기준으로 쓰지 않는다. 최종 시나리오와 수용 기준은 [`PRODUCT_EVALUATION_ENGINE_PLAN.md`](PRODUCT_EVALUATION_ENGINE_PLAN.md) §7을 따른다.

기준일: 2026-10-27. 사용자의 순서 변경에 따라 이 회차는 다음 작업이 아니라 **마지막 제품 검증**이다.
분석가 1–2명의 세션은 평가·시계열·최신성·원본/비교 Excel의 28–39회차 gate가 모두 통과한 뒤,
통합 상세 일정상 40회차에 실행한다. 참가자를 모집하거나 관찰 세션을 실행한 것은 아니다.

## 최종 세션 선행 조건

- `docs/PRODUCT_EVALUATION_ENGINE_PLAN.md`의 28–39회차 gate가 모두 통과해야 한다. 계획서나 fixture만 준비된 상태는 통과 증거가 아니다.
- 이 문서의 기존 World Bank status→CSV 시나리오는 준비 자산으로 남긴다. 세션 전에 완성된 원본/비교 workbook 명령과 실제 보존 task/series ID, 기대 sheet, 단위·주기·최신성 경고, 금지 동작, 성공·중단 조건으로 다시 쓴다.
- holdout 사례와 정답지는 참가자에게 공개하지 않는다. feedback 기록 절차를 별도로 제시하고, 피드백만으로 평가 세트나 엔진 규칙이 바뀌지 않는다고 설명한다.
- 검증된 동일 frequency/calendar의 비교 series가 없으면 의미를 추정하거나 임의 데이터를 만들지 말고 비교 과제를 제외하거나 세션을 연기한다.
- 실행 당일 최신 base SHA로 폐기 가능한 checkout을 준비하고 저장 task/raw/manifest, 빈 출력 경로, 예상 결과를 다시 확인한다. 동의와 익명 기록을 유지한다.

아래의 task ID·명령·CSV 기대값은 과거 CSV 준비 시나리오의 기록이다. 최종 세션의 base branch/SHA,
task ID, workbook 이름·sheet·기대 warning은 선행 구현이 완료된 뒤 최신 checkout에서 고정한다.

## 확인할 질문

사용자가 검증된 원자료와 비교 workbook을 열어 출처·단위·주기·최신성 경고·결측·충돌을 올바르게 해석하고, 별도 피드백을 기록할 수 있는가? 실제 workbook 명령과 저장 시리즈가 준비된 뒤 이 문서의 초기 CSV 과제를 대체한다. 참가자 성과 기준을 사전에
임의로 만들지 않고 관찰값과 실제 발언을 기록한 뒤 다음 제품 투자 우선순위를 결정한다.

## 참가자와 범위

- 대상: 반복 보고서나 정책·경제 분석에 공식 통계를 쓰는 실무자 1–2명. 저장소 작성자는 참가자로 세지 않는다.
- 시간: 1인당 약 20–30분. 진행 설명·동의, 조용한 과제 수행, 짧은 회고를 포함한다.
- 보존된 과거 과제: World Bank USA GDP 2020–2022 task `0f968a54-9855-439c-aaf2-bb7022fb5c8c`의 CSV 확인은 초기 dry-run 기록일 뿐 최종 workbook 수용 사례가 아니다. 최종 series와 task ID는 38–39회차 결과를 근거로 세션 전에 고정한다.
- task ID는 시나리오 카드로 제공한다. 현재 CLI에는 저장 task 검색·목록 기능이 없으므로 task를 찾는 능력으로 평가하지
  않는다. 이를 숨기지 말고 카드에 “이미 저장된 task”와 ID를 적는다.
- 실수집이나 `--live` 요청은 기본 과제에 넣지 않는다. 읽기 환경이 외부 네트워크를 허용하지 않으면 저장 결과 확인과
  전달만 관찰한다.

## 진행자 준비

1. 별도 임시 사본 또는 폐기 가능한 테스트 checkout을 세션 준비 당일의 최신 base 브랜치에서 만든다. 계획에 적힌 과거 SHA를
   checkout 기준으로 재사용하지 않는다. 현재 task ID는 위 World Bank 예제다. catalog는 이 task에 필요한
   task/event/artifact/validation record만 담은 폐기용 사본을 사용하고,
   실제 저장소의 DB와 raw를 참가자 checkout에서 격리한다. task가 참조하는
   `data/raw/worldbank/cd9d5a7cf3ae49e88f1bac5f795f1bdc/response.json` 및 `request.json`을 함께 보존한다.
   원본과 manifest의 해시 및 `status`/`export` 결과를 세션 직전에 다시 확인한다. task record를 만들거나 baseline을
   새로 수집해 기존 task를 대체하지 않는다.
2. task ID, 요청 기간, 기대 행 수, 결측 수, 경고(단위·주기가 unknown일 수 있음), no-overwrite 출력 경로를 진행자용
   정답지에 기록한다. 참가자에게 정답이나 다음 명령을 먼저 알려주지 않는다.
3. 출력 CSV를 새 파일명으로 저장할 수 있는지 확인한다. 기존 파일을 덮지 않도록 폴더를 비우고 `data/exports/` 아래
   새로운 파일명만 허용한다.
4. terminal 글꼴·화면 크기와 CLI 설치를 준비한다. 네트워크·API 키·외부 권한을 세션을 위해 새로 설정하지 않는다.

> 파일로 저장해 주세요. 저장한 결과에서 원본/품질 안내, 통계 단위·주기 정보, 결측과 0의 차이를 설명해 주세요.

진행자는 시작 전에 명령 사용법을 설명하지 않는다. 참가자가 도움을 요청하면 도움을 주되, 요청한 도움의 시점·내용과
도움 없이 이어서 할 수 있었는지를 기록한다. 과제 성공 자체보다 혼란·기대 불일치·오해를 관찰한다.

## 진행자 전용 기대 상태

이 절은 시나리오 안내 전에 참가자에게 보여주지 않는다. 저장 task status는 `COMPLETED`, 요청 범위는 World Bank USA GDP
2020–2022, 검증 행 수는 3, 결측은 0이다. 품질 정보에 `normalized_unit_or_frequency_unknown` 경고가 남아 있다.
완료 task의 raw response와 request manifest는 각각 위 경로에 있다. CSV는 기존 파일을 쓰지 말고 세션용 새 경로로
export한다. 예상 결과와 참가자의 설명이 다르면 정답을 먼저 알려주지 말고 발언과 화면을 기록한다.

## 자료 취급과 중단 조건

- 세션 시작 전에 목적, 기록 항목, 중단 가능성을 설명하고 동의를 받는다. 기본은 익명 메모만 기록한다. 화면·음성 녹화는
  별도 동의 없이는 하지 않는다.
- 실제 API 키, 계정, 비공개 자료, 개인 데이터는 쓰지 않는다. test checkout을 세션 뒤 폐기하며 제품 `data/`와 DB를
  직접 수정하지 않는다.
- 실수집·네트워크 권한·파일 덮어쓰기·개인 자료 입력을 요구하는 순간에는 과제를 멈추고 그 혼란을 관찰 항목으로
  기록한다. 사용자를 대신해 선택을 완료하지 않는다.

## 완료와 후속 결정

1–2회의 실제 관찰을 각각 익명 기록으로 남긴다. 관찰에서 확인한 friction, 사용자가 예상한 동작과 실제 동작의 차이,
요청한 도움, 잘못 해석한 경고를 요약한다. recurring issue가 있다고 추정하지 않고, 사례별인지 반복인지 분리한다.
그 근거로 사용자 안내 수정, CLI 보완, 추가 provider, UI 또는 자연어 투자 중 다음 한 가지를 정한다.

세션이 실행되기 전에는 사용자 이해도·시장 수요·반복 사용을 확인했다고 말하지 않는다. Gate C 자연 source revision 및
natural failure/resume 관측은 이 과제와 별도다.
