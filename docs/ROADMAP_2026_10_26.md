# MacroAtlas 제품 로드맵

기준일: 2026-10-27. 이 계획은 구현 상태표가 아니라 **무엇을 어떤 순서로 만들지** 정합니다.
사용자에게 제공할 수 있다고 말할 수 있는 범위는 [사용자 안내서](USER_GUIDE.md), 현재 완료 증거는
[구현 상태와 게이트](IMPLEMENTATION_PLAN.md)를 따릅니다.

## 제품 가설과 선택

MacroAtlas는 모든 기관을 검색하는 범용 챗봇부터 만들지 않습니다. 먼저 좁은 사용자 문제를 풉니다:
사용자가 선택한 공식 거시·금융 통계를 안전하게 가져오고, 어떤 원본·요청·검증을 거쳤는지 남겨,
반복 가능한 표로 전달합니다. 차별점은 검색 결과의 개수보다 **결과를 다시 설명하고 재현할 수 있는 출처 이력**입니다.

초기 사용자 가설은 반복 보고서·분석을 위해 기관별 자료를 직접 확인하는 경제·정책 분석가와 데이터 담당자입니다.
이 가설은 아직 사용자 인터뷰나 사용량으로 검증된 시장 사실이 아닙니다. 다음 단계에서 한 가지 업무 흐름을
실제 사용자에게 보여 주고, 범위 설정에 걸리는 시간·결과 재사용·수동 정리 시간을 확인합니다.

첫 제품 약속은 “요청한 범위가 지원되면 원본과 근거를 보존한 결과를 제공하고, 애매하거나 위험하면
이유를 설명하며 멈춘다”입니다. 지원되지 않는 범위를 그럴듯한 결과로 대체하지 않습니다.

## 지금의 기준선

2026-10-27 현재 상태는 이 문서 아래의 과거 snapshot보다 최신이며, 실행 증거는 [구현 계획](IMPLEMENTATION_PLAN.md),
[미해결 항목](UNRESOLVED_ITEMS.md), 각 pilot 보고서를 따른다. 지원 범위는 고정된 World Bank USA GDP,
BOJ FM08/FXERD01 한 달, TIC/BIS exact-scope watch와 제한된 Python API다. 제한된 CSV 전달, BIS GLI flat ZIP
한 건의 구조 보존 worker, 실행 전 시간 예측, 격리된 maintenance updater 및 동일 candidate SHA QA 경로가 구현됐다.

- 지원 경로는 고정된 World Bank USA GDP, BOJ FM08/FXERD01 한 달, TIC/BIS exact-scope watch와
  제한된 Python API입니다. 일반 자연어 검색이나 기관 전반 자동 수집은 아닙니다.
- 비API 대용량 자료의 자동 처리는 금지한다. BIS GLI flat ZIP 한 건만 명시 승인·동일 raw qualification 후 Linux 격리 worker로 구조 보존 JSONL을 만들 수 있다. `TRIAL_PASSED`만으로 정식 실행을 승인하지 않으며, 다른 provider·format과 의미 정규화는 미지원이다.
- Gate C의 D-067 제한 범위는 유지합니다. World Bank API의 저장된 natural transient failure를 같은 task/stage로
  재개한 기록은 생겼지만, TIC/BIS source revision은 관측되지 않았습니다. 자연 이벤트를 기다리며 오류를 만들어
  통과 처리하지 않습니다.
- Windows 사용자의 실측은 installer `DRY_RUN`(`registered=false`), updater `NO_ACTIONABLE_CHANGE`와 cleanup,
  90일 retention 요약, 교차 프로세스 lock 경합을 확인했다. 최신 base `f8693f0`에서 updater·retention 대상 Windows
  테스트 34개도 통과했고, base `e25d944`에서 updater run `20261027T084854Z-00b29eb9`도 Codex exit 0과
  `NO_ACTIONABLE_CHANGE`/cleanup 성공을 기록했다. Linux updater는 실제 변경 candidate를 QA한 뒤 review PR까지 전달하는 경로를 확인했다.
  Windows 사용자 세션에서 실제 candidate QA/handoff나 Task Scheduler invocation은 아직 관측하지
  않았다. 기준 HEAD `7fbd67e`의 GitHub Actions run [40464384575](https://github.com/jaeu983-lang/MacroAtlas/actions/runs/40464384575)와
  병합 commit `fb37234`의 run [40465191814](https://github.com/jaeu983-lang/MacroAtlas/actions/runs/40465191814)은 네 OS/Python job 모두
  step 실행 전에 실패했다. 이는 코드 테스트 실패나 통과 CI가 아니다. 예약 작업은 등록·활성화하지
  않는다. 상세는 [27회차 pilot 보고서](ITERATION_27_PILOT_REPORT.md)와
  [미해결 항목](UNRESOLVED_ITEMS.md)을 따른다.
- 비API 대용량 자료의 자동 처리는 제한한다. BIS GLI flat ZIP 한 건만 명시 승인·동일 raw qualification 후 Linux 격리 worker로 구조 보존 JSONL을 만들 수 있다. 다른 provider·format과 의미 정규화는 미지원이다.
- Gate C의 제한 범위는 유지한다. World Bank API의 저장된 natural transient failure를 같은 task/stage로 재개한 기록은 있지만, TIC/BIS source revision은 자연 이벤트를 기다린다. 오류를 인위적으로 만들어 통과 처리하지 않는다.
- 통합 전 변경은 제품 기본 경로로 간주하지 않는다. 열린 PR과 branch 관계는 작업 전에 원격에서 다시 확인한다.

## 개발자 유지보수 workflow의 QA 계약

유지보수 workflow는 제품 source ingestion 경로와 분리된 개발자 도구입니다. read-only analyzer와 Codex updater는 계속
분리돼 있지만, 공통 check entrypoint `python scripts/run_maintenance_qa.py`가 health·pytest·Ruff·diff·CLI를 구조화 report로
실행합니다. 이 runner는 `--base`/`--candidate` 전체 SHA를 받아 해당 snapshot을 격리 검사합니다. `run_improvement.ps1`은
전용 candidate worktree에서 변경을 제한하고 동일 SHA QA가 통과한 경우에만 push와 review PR을 생성합니다. Windows에서 확인된
항목과 미확인 candidate 경로는 위 작업표와 [27회차 pilot 보고서](ITERATION_27_PILOT_REPORT.md)를 따릅니다.
전문 API/file/large-file engines는 통합 Orchestrator 계약 아래 각자 source·format·resource 경계를 유지합니다.

[엔진 통합·분리 개선안](ENGINE_CONSOLIDATION_PLAN.md)은 control-plane 구조와 도입 순서를 기록합니다. 공통 cross-platform check,
candidate SHA QA와 updater→review PR handoff는 구현했습니다. Windows candidate 검증은 정당한 candidate가 발생할 때 진행하고,
scheduler 실행은 현재 비활성 경계를 사용자가 변경한 뒤에만 검토합니다.
사용자가 요청한 branch commit/push 자동화는 검사 통과 candidate에 한정하며, merge와 publish는 자동화하지 않습니다.

매 실행은 입력 commit, Python/OS 버전, 분석 범위, 생략/미실행 이유, 변경 파일, 테스트·정적 검사·CI 결과를
기록해야 합니다. “후보 없음”, “근거 부족”, “실행 환경 부적합”, “검사 실패”는 서로 다른 상태입니다.
새 자동화는 먼저 한 번의 로컬 dry run과 깨끗한 worktree에서 검증한 뒤 반복 주기를 정합니다. 사용자 관찰은 참가자
확보 후 별도 진행하며 이 developer workflow 개선이 제품 사용성·Gate C 근거를 대신하지 않습니다.

## 범위 밖으로 미루는 항목

- 사용자가 말로만 요청하면 임의 기관을 알아서 수집하는 범용 agent.
- XLSX·PDF·고정폭 포맷 및 모든 대용량 파일 형식의 동시 지원.
- 자연어 추론으로 통계 개념·단위·주기·최신판을 채우는 자동 보정.
- 자연 장애를 인위적으로 만들어 Gate C의 실측으로 사용하는 방식.
- 전 provider 자동 수집, 검증 전 무인 source 수집/코드 수정 scheduler, 운영 환경 자동 배포, analyzer가 제안한 코드의 자동 병합.

## 다시 계획을 여는 조건

실제 사용자가 지원 범위 밖에서 반복해서 막히거나, 기존 품질 계약으로 안전하게 처리할 수 없는 사례가 나오면
로드맵의 순서를 재검토합니다. 재검토는 코드 변경 전에 문제, 사용자, 예시 입력·출력, 실패 시 사용자 응답,
가장 작은 통합 경로, 정량 또는 관찰 가능한 완료 기준을 이 문서와 관련 요구사항에 반영합니다.

## 시간 예측의 보정과 경계

예측은 trial qualification과 BIS flat production을 각각 분리해 계산한다. preview는 최대 256 KiB의 구조 표본과
저장된 성공 task의 실제 stage wall time을 사용하고, 표본 값은 보존하지 않는다. baseline과 유사 입력 실측 후보를
모두 저장하는 shadow A/B 비교를 한다. paired forecast가 3개 쌓이기 전에는 유사 성공 실측이 3건 이상이면 경험 후보를,
아니면 warm-up baseline을 쓴다. 이후 중앙 APE가 낮은 후보를 선택한다. 이는 무작위 production 분할 실험이 아니며
실행 승인이나 자원 예산을 바꾸지 않는다.
새 엔진·기관·형식·프로세스 외 대기 시간은 이 추정의 범위가 아니다. 이력과 유사 표본이 적으면 낮은 신뢰도와
넓은 범위를 표시한다. 기간과 오차 추이는 22회차 후속 실측으로 갱신한다.
