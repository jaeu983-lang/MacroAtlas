# MacroAtlas 실행 순서 요약

> 기준일: 2026-10-27. 제품 범위·우선순위·완료 기준의 단일 기준은 [`PROJECT_PLAN.md`](../PROJECT_PLAN.md)다. 이 문서는 §11과 하위 회차 일정을 요약하며, 구현·Gate evidence는 [`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md)에 기록한다. 이전 상세 로드맵은 [`ROADMAP_2026_10_27_SNAPSHOT.md`](ROADMAP_2026_10_27_SNAPSHOT.md)에 보존한다.

## 현재 제품 상태

- 지원은 제한된 구조화 CLI/Python 경로다: World Bank 미국 GDP 1–10년, BOJ FM08/FXERD01 한 달, 제한 BLS/Census API, 요청 시 TIC/BIS 지정 파일 intake, World Bank/BOJ CSV, BIS flat ZIP 한 건의 Linux 구조 보존 worker.
- 공통 Orchestrator/EngineRegistry, task-linked SQLite feedback 기록, frequency별 기본 freshness gate, 개인정보 없는 성능 표본·보고가 구현됐다. 성능 기준선은 fixture/stored 표본으로 live API 지연을 뜻하지 않는다.
- 평가 case-set 구조 검증은 구현됐고 split별 synthetic scaffold가 있다. 검토된 사용자 feedback 사례, baseline/candidate 실행 비교, 명시 규칙 승격은 아직 완료되지 않았다.
- XLSX 원자료·비교 workbook은 미구현이다. stale 또는 freshness 미확인 최신값은 현재 제한 connector 경로에서 차단한다. Gate 판정과 세부 범위는 구현 상태 문서를 따른다.
- TIC/BIS 반복 변경 감시는 사용자 요청으로 중지됐다. 과거 unchanged 및 자연 변경 미관측 evidence는 보존하고 Gate C를 승격하지 않는다.

## 제품 구현 및 검증 순서

아래 A–G workstream은 28–39회차에서 차례로 수행한다. 각 회차는 독립 branch/worktree에서 최신 base로 시작하고, 실패한 gate를 통과 처리하지 않는다. 상세 산출물과 acceptance test는 [평가·엔진·Excel 실행 계획](PRODUCT_EVALUATION_ENGINE_PLAN.md)을 따른다.

| 회차 | 범위 | 통과 조건 |
|---:|---|---|
| 28–29 | A/B 평가 사례, split 누수 방지, 검토된 feedback을 개발 사례 초안으로 전달 | 증거·익명화·case-family 검토, version/hash 검사. 자동 사례·규칙 수정 없음 |
| 30–31 | C 동일 사례 snapshot의 baseline/candidate 비교 | 유형별 상태·순위·근거·금지 동작 비교 재현, 미목표 유형 퇴행·false-exact·금지 동작 0 |
| 32 | D 규칙 적용 심사와 rollback 기록 | reviewer, 근거, 적용 commit, validation/holdout 결과와 rollback을 연결한 명시 승인 |
| 33–37 | E typed time-series, 주기/series별 freshness, World Bank·BOJ·BLS·Census 및 파일 경계 adapter | source identity·raw/provenance·unknown 보존, injected UTC clock 경계 검증, 최신 요청의 `STALE`/`FRESHNESS_UNVERIFIED` 차단 |
| 38 | F 원자료 XLSX | 호환성·충돌·결측·정밀도·provenance 표시, no-overwrite/path guard, raw/DB 불변 |
| 39 | G 비교 XLSX | 검증 가능한 날짜 정렬·허용 변환만 기록, 빈 결측·충돌 검토, 자동 보간/forward-fill 금지 |
| 40 (23회차) | 분석가 1–2명의 최종 제품 관찰 | 28–39 gate 통과 후 완성 workbook·최신성 경고·feedback 흐름을 관찰. 동의·익명 기록, 참가자 evidence 전 사용성 통과 선언 금지 |

23회차의 현재 CSV 업무 시나리오는 준비 자산이며 최종 workbook 세션의 정답지로 사용하지 않는다. 실행 전 실제 검증 task/series ID, 명령, 기대 sheet와 경고를 고정한다. 참가자에게 holdout 사례나 정답지는 공개하지 않는다. 독립 Windows updater/scheduler pilot, 자연 Gate C evidence, 실수요 provider 확장은 A–G 제품 세션과 별도 workstream으로 유지한다.

## 별도 운영·유지보수 상태

- Windows changed-candidate/handoff 및 failure recovery는 실제 자연 변경이 있을 때 검증한다. scheduler는 비활성 상태이며 invocation을 사용 중이라고 주장하지 않는다.
- 대용량 forecast의 catalog 표본은 qualification 15건, production 1건, paired forecast 0건으로 신뢰도가 낮다. 승인된 실제 작업을 기다리며 표본 확보만을 위한 실행은 하지 않는다.
- 추가 provider/format은 반복 실수요와 공식 source contract, 자원·취소·복구 수용 기준이 확인된 경우 한 경로씩 qualification한다.
