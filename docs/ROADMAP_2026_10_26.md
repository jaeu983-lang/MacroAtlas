# MacroAtlas 실행 순서 요약

> 기준일: 2026-10-27. 이 문서는 통합 기준 [`PROJECT_PLAN.md`](../PROJECT_PLAN.md)에서 뽑은 짧은 실행 view입니다. 요구사항·우선순위·완료 기준의 단일 출처는 통합 기획서이며, 이 파일과 충돌하면 기획서를 갱신합니다. 이전 상세 로드맵은 [`ROADMAP_2026_10_27_SNAPSHOT.md`](ROADMAP_2026_10_27_SNAPSHOT.md)에 보존합니다.

## 현재 기준

- 제품 지원은 제한 구조화 CLI/Python 경로다. World Bank 미국 GDP 1–10년, BOJ FM08/FXERD01 한 달, 제한 BLS/Census API, 필요 시 요청하는 TIC/BIS 지정 파일 intake, World Bank/BOJ CSV, BIS flat ZIP 한 건의 Linux 구조 보존 worker다.
- TIC/BIS 변경상태의 반복 감시는 사용자 요청으로 중지됐다. 과거 `unchanged`와 실제 변경 미관측 기록을 보존하고 Gate C를 승격하지 않는다.
- 공통 Orchestrator/엔진 계약, SQLite feedback log, 주기별 freshness gate는 구현돼 있다. 평가 case validator도 추가됐지만 development/validation/holdout set은 비어 있으므로 실제 엔진 평가 결과는 없다.
- Gate A/D는 해당 범위에서 통과, Gate B/C/E는 제한 범위 판정이다. 정확한 증거는 [`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md)를 따른다.

## 실행 순서

아래 번호와 완료 조건은 통합 기획서 §11을 요약한다. 각 번호는 별도 High 작업이며 이전 검증이 실패하면 의존 항목을 통과 처리하지 않는다.

| 순서 | 영역 | 다음 작업 | 현재 완료 조건 |
|---:|---|---|---|
| 1 | 평가 사례 | 검토·비식별화된 사례를 development에 추가하고 validation/holdout을 근거와 함께 잠금 | 세 set에 사례가 있고 형식·누수·hash 검사가 준비 완료. 현재는 비어 있음 |
| 2 | 평가 엔진 | 공통 engine outcome과 baseline/candidate 비교기 | 동일 사례 버전에서 상태·target·ranking·근거·금지 동작 비교 |
| 3 | 규칙 관리 | 심사 기록과 적용/rollback 추적 | false confirmation·금지 동작 0건, reviewer·commit·rollback 연결 전 승격 금지 |
| 4 | 시계열 모델 | 공통 Series/ObservationBatch를 World Bank·BOJ 제한 경로부터 적용 | source·field·통화·단위·주기·달력·기간·override·provenance 보존 |
| 5 | 원자료 Excel | 개별 호환 시계열의 XLSX 출력 | source 값·결측·provenance 보존, stale/unverified 차단 |
| 6 | 비교 Excel | 호환 series sheet와 별도 alignment sheet | 변환·calendar·결측 명시, 충돌은 보존/검토, interpolation·forward-fill 금지 |
| 7 | 성능 계측 | 공통 stage 시간 및 가능한 하위 단계 시간을 engine/version별로 기록 | p50/p95·처리량·표본 수·환경·코드 SHA 보고. 20개 미만은 p95 미확정. live benchmark 요청 금지 |
| 8 | 엔진 조립 | source adapter를 위한 공통 composition registry 보완 | 계측 기준선을 보존하고 Orchestrator lifecycle·resume 회귀 유지 |
| 9 | 유지보수 | 정당한 Windows candidate의 동일 SHA QA/handoff 및 failure recovery 실측 | 실제 candidate·cleanup·no-push 실패 경로 report 확인 |
| 10 | 스케줄러 | 실제 invocation 검증은 정책 승인 후 별도 진행 | 현재 예약 작업은 비활성. 사용 중이라고 주장하지 않음 |
| 11 | 유지보수/품질 | 대용량 시간 추정과 선택된 실제 series 의미·품질 검증 | operation별 paired forecast 3건 후 재평가; unknown metadata 보존 |
| 12 | 확장 | 반복 실수요가 확인된 source 또는 format 하나를 qualification | source contract·resource/cancel/recovery·수용 테스트가 한정 범위에서 통과 |
| 13 / 23회차 | 사용자 검증 | 분석가 1–2명의 저장 결과→파일 전달 업무 관찰 | 기술 작업 뒤 마지막. 참가자 증거 없이 usability 통과 선언 금지 |
